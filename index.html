    Context

    The problem and the assumptions behind this screen

    Teams adopt AI tools faster than finance and IT can track them. Nobody can answer three questions: which AI tools are in use, who uses them, and are we within what we approved to spend? This screen answers them for a CFO, with the IT/security lead as the second reader.

    The brief left several things open, so I made these assumptions. Each one would be checked with customers in week one.

    Primary readerCFO. IT/security is secondary and is served by the shadow AI table.
    Spend limitsImported from vendor consoles where they exist. Customers can set or override them in CloudEagle.
    FreshnessDaily refresh, which matches how vendor usage APIs report.
    Shadow AIA separate list marked "spend unknown", never added to totals.
    CustomerMid-market, about 1,000 employees, 7 departments.
    Approved tools (v1)ChatGPT Enterprise and OpenAI API, Claude Enterprise and Anthropic API, Microsoft 365 and GitHub Copilot, Midjourney.
    Usage unitActive users vs paid seats. "Active" means used in the last 30 days.
    PlacementA new AI Governance tab, built on CloudEagle's existing spend and discovery data.
    Part 2

    API and data source plan

    In plain terms: we read spend and seat data from each AI vendor's admin reports, find unapproved tools from sign-in records, app permissions and expense reports, and use the HR system to group people by team. I started from the questions on the screen and worked back to the data. A person's work email links every source together.

    Terms used below: Admin API is the reporting interface a vendor gives account owners. SSO is signing in with the company account. An OAuth grant is permission a user gives an app to read company data, such as their calendar.

    Tier 3 · Context

    • HR system (Workday, BambooHR, Rippling): department, manager and employment status. This powers the department filter and catches seats held by people who have left.
    • CloudEagle's own data: budgets the customer sets, contracts and renewal dates, and the approved-apps list. That list is what makes a tool count as shadow AI.

    Rules we hold to

    • Metadata only. We never collect prompts or conversation content. Usage means who and when, not what.
    • Read-only access. Every connector asks for the narrowest read scope, and the setup screen explains why each scope is needed.
    • Show where each number comes from. Every figure carries its source and last sync time. Weak sources are labelled, not hidden.

    Known gaps

    • API keys aren't people. API spend attaches to a project or key, so the screen attributes it project by project. The customer maps each project to an owning team.
    • Personal accounts (free ChatGPT on a personal email) are invisible to SSO and vendor APIs. Only the browser extension or a network gateway can see them.
    • Midjourney has no admin API and no SSO, so we rely on expenses alone. That's why it's marked low confidence.
    • Identity mismatch: GitHub handles and email aliases need matching rules, plus a manual review queue for the rest.
    Part 3

    The three charts, and why

    The test for each chart was whether it leads the CFO to a decision. Together they cover this month, the direction of travel, and waste.

    Chart 1

    Spend vs limit by tool

    Question
    Which tools will go over their limit this month?
    Decision
    Raise the limit, cap usage, or talk to the owning team.
    Why this form
    Bullet bars put spend, the projection and the limit in one row, on a shared "% of limit" scale. The limit marker shows whether it actually stops spend (vendor cap) or only alerts (CloudEagle budget).
    Chart 2

    Spend trend and forecast

    Question
    How fast is AI spend growing, and when will it go over budget?
    Decision
    Set next quarter's budget, or negotiate an enterprise agreement before growth forces it.
    Why this form
    Stacked columns show the total and the mix together. The budget line and a dashed forecast make the month spend crosses the budget easy to see.
    Chart 3

    Seat utilisation

    Question
    Are we paying for seats nobody uses?
    Decision
    Reclaim seats now, especially from people who have left, or reduce the count at renewal.
    Why this form
    Active vs idle bars, each labelled with the monthly cost of idle seats. It turns usage into money, and it's where CloudEagle's savings come from.

    On the screen, but not charts

    • Needs attention and the four key numbers are text and figures that summarise the charts.
    • Shadow AI is a table with actions. Each row needs a decision, which a list handles better than a chart.
    • Department is a filter that applies to the whole screen.

    Charts I left out

    ChartWhy it's not here
    Pie or donut of spend shareShows no limit, and slices are hard to compare
    GaugesOne number per graphic. Chart 1 shows every tool in the same space.
    Token or API-call volumeNot the CFO's unit, and can't be compared across seat-based tools
    Top users leaderboardInvites blame and privacy concerns. Individuals appear only in drill-downs.
    Shadow AI chartPeople need to act on these, so a table with actions works better
    Spend by departmentHandled by the department filter

    Trade-off: there is no chart dedicated to security risk. That follows from making the CFO the primary reader. A security-first version would swap Chart 2 for a chart of risky access over time.
